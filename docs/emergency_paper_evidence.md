# Evidence audit for the TAS 2026 short paper

Every numeric claim in `paper/main.tex` traces to a row below. No number enters
the paper without an artifact. Regenerate all of it with:

```
uv run python scripts/paper/reproduce_all.py
```

E1–E3 need a local Docker daemon plus the image
`swebench/sweb.eval.x86_64.matplotlib_1776_matplotlib-23412:latest`.
E4–E5 are pure Python and run anywhere. **No paid API is used by any experiment.**

---

## E1 — omitted official `test_patch`

- **CLAIM:** Without the official `test_patch`, the `FAIL_TO_PASS` node id does
  not exist; pytest exits 4 with "no tests ran". With it, exit 1 and 1 failed.
- **ARTIFACT:** `results/paper/e1_test_patch_effect.json`,
  raw logs in `results/paper/e1_raw/`
- **COMMAND:** `python scripts/paper/reproduce_all.py --only e1`
- **EXACT RESULT:**
  - `without_test_patch`: `success=false`, `tests_failed=null`, `score=0.0`;
    raw shows `exit_status: 4`, `no tests ran`, `ERROR: not found`
  - `with_test_patch`: `success=false`, `tests_failed=1`, `score=0.0`;
    raw shows `exit_status: 1`, `1 failed`
- **LIMITATION:** One instance (`matplotlib__matplotlib-23412`). Demonstrates the
  mechanism, not how many SWE-bench instances are affected. Both arms are
  `success=false`, so the harm requires a downstream consumer that reads
  absence-of-failure as success — we assert that as a risk, not as observed
  practice in any specific published harness.

## E2 — pipeline exit-code masking

- **CLAIM:** Without `set -o pipefail`, a failing command piped into `tail`
  reports exit 0.
- **ARTIFACT:** `results/paper/e2_pipeline_exit_code.json`
- **COMMAND:** `python scripts/paper/reproduce_all.py --only e2`
- **EXACT RESULT:** `false | tail -5` → **1** with pipefail, **0** without.
  `python -c "sys.exit(1)" | tail -5` → **1** / **0**. `true | tail -5` → 0 / 0.
  `commands_whose_failure_is_masked` = 2 of 3.
- **LIMITATION:** Standard POSIX shell semantics, not a novel discovery. The
  contribution is that an agent harness recording raw shell status inherits it
  silently. Measured inside the benchmark container, bash.

## E3 — container-wide change attribution

- **CLAIM:** `docker diff` attributes environment churn to the agent; a
  repository-scoped git measurement does not.
- **ARTIFACT:** `results/paper/e3_repo_scoped_changes.json`
- **COMMAND:** `python scripts/paper/reproduce_all.py --only e3`
- **EXACT RESULT:** container-wide `docker diff`: 0 at start → **32** after a
  command touching no repository file → 33 after one source edit.
  Repository-scoped git: 0 → **0** → **1 file, 2 lines added**, `measured=true`.
  `container_wide_inflation_from_churn = 32`, `repo_scoped_inflation_from_churn = 0`.
- **SECONDARY CLAIM (historical):** an earlier real agent run recorded
  `files_changed = 537` at step 3, dominated by conda/pytest-cache churn.
- **ARTIFACT (historical):** `docs/phase0_5_report.md`, section "D1
  repository-change fix". This value is from an earlier run and is **not**
  regenerated by `reproduce_all.py`; the paper labels it as such.
- **LIMITATION:** The 32-file churn figure depends on the image and the exact
  warm-up command; it is an existence demonstration, not a stable constant.

## E4 — oracle / future leakage

- **CLAIM:** Appending 20 maximally predictive future steps changes 0 of 24
  online features computed from a length-3 prefix.
- **ARTIFACT:** `results/paper/e4_oracle_leakage.json`
- **COMMAND:** `python scripts/paper/reproduce_all.py --only e4`
- **EXACT RESULT:** `prefix_length_k=3`, `future_steps_appended=20`,
  `n_features_compared=24`, `features_changed_by_future_information={}`,
  `prefix_len_stays=3`, `reading_step_at_or_beyond_cut_raises=true`
  (`PrefixBoundaryError`), `outcome_attributes_exposed_on_prefix=[]`.
- **LIMITATION:** An adversarial regression test over the implemented feature
  set, not a proof of non-leakage for arbitrary future features. It shows the
  path is closed by construction (type-level) for the 24 features that exist.

## E5 — infrastructure-invalid label contamination

- **CLAIM:** All three provider-infrastructure terminations are structurally
  refused a `Y_success` label; the five agent-semantic reasons accept one; 0
  violations. 8 real recorded sessions terminated on provider quota and carry no
  label.
- **ARTIFACT:** `results/paper/e5_infrastructure_invalid_labels.json`;
  observed runs from `artifacts/phase0_5/scientific_run_dispositions.json`
- **COMMAND:** `python scripts/paper/reproduce_all.py --only e5`
- **EXACT RESULT:** `PROVIDER_RATE_LIMITED`, `PROVIDER_TIMEOUT`,
  `PROVIDER_UNAVAILABLE` → `labelling_with_y_success_allowed=false`.
  `cost_limit`, `crash`, `step_limit`, `submitted`, `timeout` → `true`.
  `invariant_violations=[]`. Observed: 8 sessions, `all_invalid=true`,
  `all_unlabelled=true`, reasons `["PROVIDER_RATE_LIMITED"]`.
- **LIMITATION:** The 8 sessions are from one free-tier account on one provider.
  They are a case study in infrastructure/label separation, **not** an estimate
  of that provider's reliability. The paper states this explicitly.

## Claims deliberately NOT made

- No agent success rate, capability, or benchmark score.
- No provider reliability statistic or comparison.
- No prevalence estimate for any defect in any published harness.
- No replay-stability result: our same-condition continuations were terminated
  by provider quota before yielding valid comparisons (0 of 6 valid).
- No predictor, scheduler, or compute-saving claim.
- No "first to observe" claim for any individual defect.
